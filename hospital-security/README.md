# CareShield SOC: hospital cybersecurity & phishing detection

A defensive security platform for healthcare. It classifies phishing e-mails and malicious URLs with trained
models, detects network intrusions in Zeek/Suricata telemetry and CICFlowMeter CSVs, applies ransomware and
access-abuse rules to Sysmon and authentication events, and correlates the results. Correlated alerts stream
live to a dashboard for analyst review.

* **Backend:** FastAPI, SQLAlchemy 2, Alembic, PostgreSQL (SQLite for local dev), WebSocket + SSE
* **ML:** scikit-learn, XGBoost, pandas; TF-IDF text models
* **Frontend:** Next.js 15 (App Router) + TypeScript, Tailwind CSS v4, Recharts, light green/teal theme (no black or blue)
* **Deployment:** Docker Compose (PostgreSQL, API, dashboard, optional Suricata sensor)

> Alerts are detections for human review, never confirmed incidents. The platform does not block hosts,
> quarantine files, change firewall rules or touch clinical systems. An analyst confirms or dismisses each
> incident, and containment goes through your approved change process.

## 1. What is implemented

| Module | Method | Data it was trained or validated on |
|---|---|---|
| Phishing / malicious e-mail | TF-IDF (1–2-grams) with Logistic Regression, linear SVM (Platt-calibrated) and Complement NB compared; the best validation PR-AUC is kept. Rule indicators: urgency, credential requests, display-name impersonation, Reply-To mismatch, SPF/DKIM/DMARC failures, IP or shortened links, link-text mismatch, risky attachments | Enron-Spam (6 mailboxes) |
| Malicious URL (never visited) | 36 lexical features + char n-gram TF-IDF; LR baseline, XGBoost, n-gram LR and a blend compared; isotonic calibration. Optional URLhaus enrichment | Sahingoz et al. 2019 phishing URL dataset |
| Network intrusion | Logistic-regression baseline, Random Forest and XGBoost on 7 categories (benign, brute force, web attack, DoS, DDoS, botnet, infiltration) | CSE-CIC-IDS2018 (official AWS bucket) |
| Live network telemetry | Suricata EVE + Zeek tailers / push API → portable 12-feature flow model + Suricata signature alerts + domain observations | Verified live with Suricata 7.0.3 (see §6) |
| Hospital monitoring | Versioned rules: failed-login bursts, password spraying, success-after-failures, off-hours privileged login, many-hosts access, large uploads (exfiltration), clinical-device egress, non-approved outbound ports | Synthetic events |
| Ransomware / endpoint | Sysmon rules: shadow-copy and backup deletion, recovery disabled, mass file writes with ransomware extensions, ransom notes, log clearing, Defender tampering, Office → shell, encoded PowerShell | Synthetic events only. **No ML model**: no suitable labelled public dataset exists (see `docs/datasets.md`) |
| Correlation | Alerts that share an IP, host, user, domain or URL within a window become an incident. A DNS/HTTP/TLS lookup of a domain flagged by an e-mail, URL or URLhaus alert raises a "contacted flagged domain" alert. Severity goes up one level when independent modules agree | — |

Pipeline: incoming event or submission → Pydantic validation and size limits → feature extraction → trained
model or rule → risk score and severity (configurable thresholds) → alert (de-duplicated within a suppression
window) → database → correlation → WebSocket/SSE push → dashboard.

Every dashboard number comes from the database or from a training run's report file. There are no hardcoded
predictions and no random alert generation.

## 2. Measured results (held-out data, generated by the training scripts)

Full reports with confusion matrices are in `ml/reports/*.md` and on the dashboard's **Model performance**
page. Thresholds are chosen on **validation** data as the lowest score whose false-positive rate is ≤ 1 %,
then applied unchanged to the test split.

**E-mail** (selected: TF-IDF + Complement NB). Source-held-out test: mailboxes enron5 and enron6, 8,722 messages never seen in training.

| Model | Precision | Recall | F1 | FPR | PR-AUC |
|---|---|---|---|---|---|
| TF-IDF + Logistic Regression (baseline) | 0.9878 | 0.9935 | 0.9906 | 0.0264 | 0.9991 |
| TF-IDF + linear SVM | 0.9885 | 0.9943 | 0.9914 | 0.0249 | 0.9991 |
| **TF-IDF + Complement NB (selected)** | 0.9875 | 0.9921 | 0.9898 | 0.0271 | 0.9993 |

The test FPR (2.7 %) is higher than the 1 % validation target. Different mailboxes have a different
legitimate-mail style, and this source-based split exposes that shift. Mean latency is 2.1 ms per message.

**URL** (selected: char n-gram LR, isotonic-calibrated). The test set contains 7,789 URLs from registered domains not in train or validation.

| Model | Precision | Recall | F1 | FPR | PR-AUC |
|---|---|---|---|---|---|
| Lexical features + LR (baseline) | 0.9799 | 0.6017 | 0.7456 | 0.0104 | 0.9595 |
| Lexical features + XGBoost | 0.9832 | 0.7393 | 0.8440 | 0.0107 | 0.9766 |
| **Char n-gram + LR (selected)** | 0.9924 | 0.9201 | 0.9549 | 0.0059 | 0.9947 |
| Blend XGBoost + n-gram | 0.9864 | 0.9148 | 0.9493 | 0.0107 | 0.9942 |

After calibration: precision 0.9951, recall 0.9041, FPR 0.0038, ROC-AUC 0.9947, mean latency 1.0 ms.
Recall is only 0.32 on bare host names with no path (88 phishing examples): a known weakness.

**Network, 77 CICFlowMeter features** (selected: XGBoost). Time-ordered test split of 123,974 flows.

| Model | Macro F1 | Attack precision | Attack recall | Benign FPR | Attack PR-AUC |
|---|---|---|---|---|---|
| Logistic regression (baseline) | 0.7558 | 0.9864 | 0.8510 | 0.0085 | 0.9603 |
| Random Forest | 0.8401 | 0.9861 | 0.8455 | 0.0086 | 0.9790 |
| **XGBoost (selected)** | 0.8644 | 0.9861 | 0.8663 | 0.0088 | 0.9809 |

Per-category recall: brute force 0.999, botnet 1.000, DDoS 0.995, DoS 0.992, web attack 0.857, **infiltration
0.141**. Infiltration flows look like benign traffic at the flow level. This is a known property of the dataset and is documented in the report. Mean latency is 1.35 ms per flow.

**Network, 12 portable features for Zeek/Suricata** (selected: Random Forest). Macro F1 0.7613, attack
precision 0.9846, recall 0.8439, benign FPR 0.0096, PR-AUC 0.9689, mean latency 6.0 ms per flow. Losing
the timing and flag features costs mainly web-attack precision (0.29) and infiltration recall (0.06).

## 3. Quick start with Docker

```bash
cd hospital-security
cp .env.example .env
# edit .env: POSTGRES_PASSWORD, JWT_SECRET (python -c "import secrets;print(secrets.token_urlsafe(48))"),
#            BOOTSTRAP_ADMIN_EMAIL / BOOTSTRAP_ADMIN_PASSWORD (>= 12 chars)
docker compose up --build -d
open http://localhost:3000            # dashboard; API docs at http://localhost:8000/docs
```

The trained artifacts in `ml/artifacts/` are baked into the backend image, and migrations run on start-up.
Behind a TLS-inspecting proxy, set `EXTRA_CA_CERT=<path to CA file inside this directory>` in `.env` so the
image builds can reach PyPI and npm.

Optional live sensor (authorised networks only): set `SURICATA_EVE_PATH=/var/log/suricata/eve.json` in `.env`, then
`SURICATA_INTERFACE=eth0 docker compose --profile suricata up -d`.

Roles: **admin** (users, settings, audit log, feed refresh), **analyst** (submit analyses, ingest, triage
alerts and incidents), **viewer** (read-only).

## 5. Training and evaluation (reproducible)

```bash
cd hospital-security
python -m ml.data.download --all                 # ~2.7 GB; unreachable sources are reported and skipped
python -m ml.preprocessing.prepare_cic2018        # clean, de-duplicate, sample, time-ordered split
python -m ml.training.train_email                 # ~1 min
python -m ml.training.train_url                   # ~3 min
python -m ml.training.train_network               # ~8 min, trains network_cic and network_portable
```

Each run writes `ml/artifacts/<model>/<version>/{model.joblib,metadata.json}` and points `LATEST` at the new
version. Metadata records datasets, input hashes, split, threshold, metrics, latency and limitations, and the
run also writes `ml/reports/<model>.{md,json}` (history in `ml/reports/history/`). The API checks the artifact's
SHA-256 before loading it. Pin a version with `MODEL_VERSION_<NAME>=<version>`, otherwise `LATEST` is used.
Restart the API after retraining.

Leakage controls: exact-duplicate removal before splitting in every pipeline; a source-held-out split for
e-mail (different mailboxes); a split grouped by registered domain for URLs; a time-ordered per-(day,
label) split for flows. Threshold and model selection use validation data only.

## 6. Live telemetry

Configure any of `SURICATA_EVE_PATH`, `ZEEK_LOG_DIR`, `SYSMON_LOG_PATH`, or push events to
`/api/v1/ingest/{suricata,zeek,sysmon,auth}` with `X-API-Key` (keys come from `INGEST_API_KEYS`). Connection health,
freshness, duplicate and error counts appear on the Overview and Network pages.

**Verified here:** Suricata 7.0.3 captured live traffic on the development container's loopback interface,
and the tailer ingested its `eve.json` while traffic was generated: 90/90 events with 0 errors, rule alerts
within seconds, and flows scored by the model. **Not verified live:** Zeek (no package was available for the
build OS; parsers are tested with format-accurate records), Sysmon and authentication sources (synthetic
events only). Mapping details and limits: `docs/telemetry-compatibility.md`.

## 7. Demonstration mode (clearly simulated)

```bash
python scripts/demo_replay.py --email <analyst or admin e-mail> --password <password>
```

This replays held-out CSE-CIC-IDS2018 test flows as Suricata EVE events, plus a synthetic Sysmon ransomware
sequence, an EHR brute-force burst and a phishing e-mail followed by a DNS lookup of its link. The events
go through the normal pipeline. Every event is stored with `is_simulated=true`, and the dashboard shows a
**SIMULATED** badge and an "Include simulated data" toggle. No malware is executed.

## 8. Tests

```bash
cd hospital-security
python -m pytest                                   # 90 backend/ML tests (SQLite)
TEST_DATABASE_URL=postgresql+psycopg://user@host/emptydb python -m pytest   # same suite on PostgreSQL
cd frontend && npm run typecheck && npm run lint && npm test && npm run build
```

The backend suite covers feature extraction; model loading, checksum tampering and **re-scoring the
held-out sets to reproduce the stored reports exactly**; auth (401/403 per role, CSRF header for cookie
sessions, sensor keys, login rate limit, audit of failed logins); malformed, oversized and invalid inputs (422/413/415);
response schemas; alert persistence, aggregation, workflow and WebSocket delivery; Zeek/Suricata/Sysmon/auth
ingestion with de-duplication; tailer rotation, partial lines, missing files and error retry; URLhaus
unreachable, 401 and 429 handling; correlation into incidents; and false-positive/negative feedback
reporting. The frontend tests cover loading, error, empty and success states and the API client.

## 9. Security and privacy controls

* JWT in an httpOnly, SameSite=Strict cookie (or a Bearer header for API clients); bcrypt passwords; three roles,
  least privilege; `X-Requested-With` required for cookie-authenticated writes; WebSocket Origin check.
* In production (`ENVIRONMENT=production`) the API refuses to start without a strong `JWT_SECRET` and
  `COOKIE_SECURE=true`. Terminate TLS at a reverse proxy, and use encrypted volumes or managed PostgreSQL
  encryption for data at rest.
* Per-IP rate limits (stricter on login), request-body and upload limits, CSV row limits, Pydantic field limits.
* E-mail content is **not stored** by default: only a hash, the sender domain, indicators and the score
  (`STORE_RAW_EMAIL`). URLs are analysed as text and never fetched. Attachments are listed by name, never opened.
* Configurable retention for alerts, analyses, telemetry and audit logs, applied daily or on demand.
* Every login, analysis, alert and incident change, settings change and user change is in the audit log.
* No patient data is used anywhere. Use synthetic data for demonstrations.

## 12. Limitations and next steps

* Re-train on recent, locally labelled data before production use. The training corpora are from 1999–2005 (e-mail), 2017–2018 (URLs) and 2018 (flows).
* The e-mail model learned spam vs. legitimate mail. Phishing-specific evidence comes from the rule indicators. Adding SpamAssassin or a phishing corpus requires reaching its official host.
* URLhaus enrichment needs a free Auth-Key and network access to abuse.ch, both unavailable in the build environment.
* Zeek, Sysmon and authentication sources need verification against real authorised sensors.
* Single API process: the live-alert hub and the rate-limit/rule windows are in memory. Use Redis (pub/sub and counters) before running several replicas.
* Infiltration detection from flow data is weak (recall 0.14 / 0.06); it needs host telemetry.
